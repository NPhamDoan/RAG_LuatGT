# Provider HTTP base class, pipeline split, and git-provenance removal

Refactor of `backend/app` (commit `b10ee23` vs parent `a748b2d`) that extracts a shared `HttpLLMProvider` for Mistral/Cohere, splits `QueryPipeline._answer` into `_gate`/`_synthesize`, splits `DocumentPipeline.process_document` into three helpers, drops the `seedGitBranch`/`seedGitCommit` provenance fields (backend + frontend), deletes unused enrich-import helpers, and makes the embedding dimension a constructor parameter. The 39-test suite passes at `b10ee23`. Payloads, headers, error handling, gating thresholds, confidence labels and seed metadata ordering are preserved; the differences that remain are one small behavior change in `chunk_only`, one test-seam crash path in `enrich_step.build_auto`, and several log-format changes.

Watch for: `chunk_only` now enforces the 50 MB size limit it previously skipped (confirmed, low); `build_auto` with `settings=None` and `ENRICH_LLM_PROVIDER=groq` + empty `ENRICH_LLM_API_KEY` now raises `AttributeError` where it used to return `''` (confirmed, test-only path); trace prefix changed from `[phase:pipeline]` to `[pipeline]` and the gating trace no longer prints `max_score` (confirmed, log-only); Mistral/Cohere log lines now come from logger `app.providers._http_base` instead of the per-provider module (confirmed, log-only).

**Verdict**: APPROVED

## High-level view

Mistral and Cohere are now thin subclasses of `HttpLLMProvider` (`_http_base.py`), which owns the payload (`model`, `messages`, `temperature=0.2`, `max_tokens`), the three headers, the `HTTPStatusError` → `text[:300]` log → re-raise and `HTTPError` → log → re-raise paths, and the empty-content warning. Each subclass only supplies `_extract`; Cohere still joins `type=="text"` blocks and strips, Mistral still reads `choices[0].message.content`. Groq and Ollama only swapped their inline message construction for `build_messages`, which produces the same list. The one observable difference is the logger name on Mistral/Cohere lines.

`QueryPipeline._answer` dedupes first (skipped when empty), then `_gate` handles the three early-return cases (no results, `< threshold_min`, `< threshold_confident`) with the same messages and `doTinCay`, then `_calc_confidence` is called on `max(score)` of the same deduped list before `_synthesize`. The try/except/fallback body is unchanged. Only the trace strings changed.

`DocumentPipeline.process_document` keeps the exact order: size → format → `exists` → duplicate error → parse → chunk → index steps (sets `_last_steps`) → embed → delete-if-replace → `add_chunks(extra_metadata=_seed_metadata())`. `chunk_only` now reuses `_validate_upload`, which adds the size check it did not have before. `_git_info`, `subprocess` and the two `seedGit*` fields are gone with no remaining references in backend, frontend or scripts.

`enrich_step.build_auto` replaced a `getattr(settings, "primary_llm_api_key", "")` fallback (an attribute that never existed on `Settings`, so it always returned `''`) with `settings.resolve_llm("groq").api_key`. In production this is a fix: an empty `ENRICH_LLM_API_KEY` now reuses `GROQ_API_KEY` instead of building a Groq client with no key. With `settings=None` it crashes at build time; only tests construct `IndexDeps` that way, and the existing groq test sets a dummy key so the path is not exercised.

Removed symbols (`StepDeps.verify_llm`, `BaseStep`, `create_verify_llm`, `parse_import_text`, `apply_enrich_to_jsonl`, `_write_jsonl`) have no remaining importers. `json` in `enrich_io.py` is still used by `_read_jsonl`. `HuggingFaceEmbedding(dimension=...)` defaults to 1024, so the unchanged call in `seed_data.py` still works. Console and file log handlers are already UTF-8, so the switch to diacritics in provider docstrings/log strings is cosmetic.

### HttpLLMProvider extraction (Mistral, Cohere, Groq, Ollama)

Payload (`_http_base.py:64-69`), headers (`:78-82`), the two except blocks with `[:300]` preview (`:91-100`), and the empty-content warning match the removed Mistral/Cohere code. `CohereProvider._extract` (`cohere_provider.py:28-34`) keeps the `type=="text"` filter, `.strip()`, and top-level `finish_reason`; `MistralProvider._extract` (`mistral_provider.py:27-30`) keeps `choices[0].message.content` with `or ""` and the choice-level `finish_reason`. Groq and Ollama only swapped in `build_messages`, which yields the same `[system?, user]` list.

The one observable difference is the logger name: `mistral_provider`/`cohere_provider` lines now originate from `app.providers._http_base` (confirmed, log-only). `HttpLLMProvider` has no test of its own, so this equivalence rests on reading, not on a payload/error-path assertion.

### Gating and synthesis split

Dedupe moved ahead of the empty check (`query_pipeline.py:98`), guarded by `if results else []`, so the empty path still reaches `_no_results()` via `_gate`. `max_score` is computed twice (once in `_gate`, once in `_answer` for `_calc_confidence`) over the same deduped list; dedupe is deterministic and non-mutating, so both values agree (confirmed). Threshold messages, `doTinCay` values and the `_synthesize` try/except/fallback body are unchanged.

Trace changes (confirmed, log-only): `_trace` format `"[phase:%s] "` → `"[%s] "` at line 52; the pre-synthesis trace at line 138 no longer includes `max_score`. `.env.example:91` still references `"[phase:...]"`.

### Document pipeline split and provenance removal

`_run_index_steps` (`document_pipeline.py:141-156`) assigns `self._last_steps` before iterating, and `_seed_metadata()` is evaluated as the `add_chunks` argument afterwards, so the manifest still reflects the current request's override.

`chunk_only` (`document_pipeline.py:186-194`) changed behavior: it now calls `_validate_upload`, which includes the `len(file_content) > _max_file_size_bytes` check. Previously `chunk_only` only validated the extension. The route at `documents.py` catches `DocumentPipelineError` and returns 400, so the effect is that oversized files sent to `enrich-export-upload` are rejected instead of chunked (confirmed, low severity, arguably a fix since `process_document` would reject the same file later).

`seedGitBranch`/`seedGitCommit` are gone from `_SEED_FIELDS`, the TS type and `AdminPage.SeedInfo`; `git grep` at `b10ee23` finds no remaining references. Existing ChromaDB rows that already carry those keys keep them in storage but they are no longer projected to the API. `lru_cache` was not imported in the parent, so there was nothing to remove.

### Enrich build_auto key fallback

At `a748b2d`, `Settings` had no `primary_llm_api_key` attribute (`git grep` finds the name only in `enrich_step.py`), so the old fallback was dead: it always produced `''`, and `GroqProvider` was built with an empty key, failing per-chunk at call time with the chunk kept unenriched. The new `deps.settings.resolve_llm("groq").api_key` (`enrich_step.py:299`) returns `GROQ_API_KEY`, so production enrich-with-groq now works without a duplicate key. `resolve_llm("groq")` cannot raise for a real `Settings`; it only raises `ValueError` for unknown names.

Reproduced at `b10ee23`: `build_auto(IndexDeps(settings=None, ...))` with `ENRICH_LLM_PROVIDER=groq` and empty `ENRICH_LLM_API_KEY` raises `AttributeError: 'NoneType' object has no attribute 'resolve_llm'` (confirmed). All five `settings=None` constructions are in tests; `main.py:61` and `seed_data.py` pass real `Settings`. The existing groq test (`test_enrich_step.py:63-73`) sets `ENRICH_LLM_API_KEY=dummy-key`, so the suite does not hit the path. Not a production regression.

### Dead-symbol removal and remaining importers

`StepDeps.verify_llm`, `BaseStep`, `create_verify_llm`, `parse_import_text`, `apply_enrich_to_jsonl`, `_write_jsonl`: `git grep` at `b10ee23` returns no importers in `backend/`, `frontend/src`, or root scripts. `json` in `enrich_io.py` is still used by `_read_jsonl`. The `_write_jsonl` names at `tests/test_enrich_io.py:11` and `tests/test_enrich_step.py:105` are local test helpers, not the deleted function. The rewrite of `test_enrich_io.py` dropped the export→fill→parse roundtrip test; `parse_import_filtered` is now only tested on hand-written block text, not on `build_export_text` output.

### Embedding dimension parameter

`seed_data.py:80` still calls `HuggingFaceEmbedding(model_name=...)` without `dimension` and gets the 1024 default, while `main.py:43-45` passes `settings.embedding_dimension`. Nothing breaks today, but if `EMBEDDING_MODEL`/`EMBEDDING_DIMENSION` are ever changed together, the seed script and the server will disagree on `get_dimension()` (possible; only matters if the model changes). Tests use `FakeEmbedding` and are unaffected.

### Test coverage

39 tests pass at `b10ee23`. Covered: gating/synthesis/fallback via fakes, document pipeline step ordering with one index step, enrich build with/without dedicated provider, hybrid search, enrich export/parse. Not tested: `HttpLLMProvider` itself (no HTTP-level test for Mistral/Cohere payload or error paths); `chunk_only`'s new size check; `_rename_so_hieu`; the `build_auto` groq path with an empty `ENRICH_LLM_API_KEY`.
